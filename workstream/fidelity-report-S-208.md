## 1. Human-readable summary

This story lets the code-review agent use the verifier's report without doing the verifier's job again. For each issue a pull request closes, the agent looks for that story's fidelity report and that issue's fidelity report. It ignores roll-up reports. It finds the report's drift section and picks out every row rated both "Critical" and "Unintended". Those rows are the only drift the reviewer will be asked to check, and only they can make the review blocking. The rest of the drift is counted, not repeated. The whole drift section is also passed along, within a size limit, as background. If there is no report, the agent records "no report". If the report has no recognisable drift section, the agent records "not parseable" and does not guess.

The story also gathers the repository's house rules: `AGENTS.md`, or `CLAUDE.md` if there is no `AGENTS.md`, plus the title and status of up to 50 architecture decision records. All of this is kept to 10% of the review's size allowance.

Everything the story asked for is present and tested, and the independent re-run passes. Four changes from the written plan were deliberate. The most important one: the spec's rule for finding the drift section did not accept numbered headings such as "3. Drift catalog". Every report the verifier has written for this PRD uses that numbered form, so under the spec's rule every one of them would have been "not parseable". The team widened the rule (decision D-44, not yet logged). The other deliberate changes: a "permission denied" answer on a report is treated like a missing report but flagged, rows are numbered across all tables in the drift section, and the test plan's expectation for numbered headings is now out of date. Testing also found four weaknesses against deliberately hostile files, and an oversized-ADR gap. All of them are fixed.

None of the differences lets the agent hide or invent a critical finding. Each should be written back into the spec, story, or test plan. One small weakness of the same kind was found in the code from the previous story (S-207), and it should be fixed separately.
