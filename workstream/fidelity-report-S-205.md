## 1. Human-readable summary

This story gives the code-review agent the single doorway it uses to talk to GitHub. Through that doorway the agent can read a pull request, its changed files, file contents, folder listings, and linked issues. It can make exactly one kind of change: posting a comment on the pull request it was asked to review. Anything else, such as approving, merging, pushing, labelling, commenting on a different issue, or touching another repository, is refused before any request leaves the agent. That holds even if a bug or a malicious instruction hidden in the code under review tries to steer it.

When GitHub is briefly unavailable or asks the agent to slow down, the agent tries a read up to three times and waits no longer than 30 seconds between tries. It never repeats the comment, so a hiccup cannot produce a duplicate. Errors are sorted into "GitHub refused permission" and "GitHub failed", and no error message ever contains the agent's access key. File names from the pull request are only ever sent to GitHub, safely encoded, and never opened on the agent's own disk.

Everything the story asked for is present and tested, and the independent re-run passes. The developer also fixed a small mislabelling in how the agent reports a rejected sign-in to GitHub. That fix means this agent's copy of the sign-in module now differs from the one it was copied from, which should be recorded. A few behaviors go slightly beyond the written spec. The main ones: "not found" is reported as its own kind of result, and a "slow down" response from GitHub is also honored in its standard form. They are sensible, but the spec and later stories should name them so the next stories handle them on purpose.
