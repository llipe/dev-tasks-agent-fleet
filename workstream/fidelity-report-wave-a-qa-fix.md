## 1. Human-readable summary

The final quality check for Wave A found two small problems. This branch fixes both and adds the tests that were missing.

1. **The comment size figure could be wrong.** Each run records how long its posted review comment is. When the agent removed a secret from the comment at the last moment, the figure was the length from before the removal, so it was slightly too big. The figure is now measured on the comment exactly as posted, the same way the other comment types already did it.
2. **A disguised secret could reach the stored review.** Someone could hide a secret by putting invisible characters between its letters. The posted comment was already safe. The copy of the review saved for the panel was not, and a viewer that ignores those characters would show the whole secret. The agent now removes the invisible characters wherever doing so exposes a secret, and only then. It does this before anything is written or posted.
3. **New tests for errors after posting.** Some errors can happen after the review comment is already on the pull request. The new tests prove that the run still counts as a success, that no second "failed" comment is posted, and that the run is recorded only once.

What is left is one question about how wide "invisible characters" should be (DR-1) and two documents that need their text brought up to date (DR-2, DR-3).

### Judgment on the developer's choices

- **The strip set includes bidi controls and shares `render._DROPPED`: correct.** The spec's DF-19 (§8.8, "Neutralization") names this exact set: bidi controls, U+200B to U+200D, U+2060, U+FEFF, and the tag block. Sharing one table means the scrub sees what the renderer shows. `test_strip_invisible_is_exactly_the_set_neutralize_drops` pins the two sets as equal, so they cannot drift apart. It is narrower than the QA report's suggested "Unicode `Cf`" (DR-1).
- **Text is stripped only when stripping reveals a secret: correct and well bounded.** Text that hides no secret (a canonical path with a zero-width character) keeps its characters in the artifact, so panel paths stay true to the repository. When a secret is revealed, the whole string loses its invisible characters, not only the secret. That is acceptable, because `neutralize` drops them from the comment anyway. Because the check runs after `validate`, the location match on raw paths is not affected.
- **Tests turn off `strip_invisible` to exercise the post-render scrub path: sound.** After QA-PRD-02, model text can no longer reach `_scrub_body` with a split secret, so the post-render scrub is defense in depth for forms only the renderer could create. Monkeypatching `pipeline.strip_invisible` is a test-only seam. It works because `_scrub_text` looks the name up in the module at call time. The parametrized test also keeps the default (pre-render) path under test, and tells the two paths apart by an escaped `***` versus a literal one. The QA-PRD-01 fix is structural (it measures the posted body), so it holds on any path where the post-render scrub changes the body.
- **`scrubber.py` is unchanged: correct.** It is vendored and shared with the sibling agents. The wrapper keeps the change local to `code-review`.
