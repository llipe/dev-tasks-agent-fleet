# Traceability Matrix — Bug Fix Agent (verifier, Design Mode)

> Companion to [`test-plan-prd-bug-fix-agent.md`](test-plan-prd-bug-fix-agent.md) v1.1. It maps:
> - **PRD FR → PRD AC → story AC → test case IDs → layer → file** (§A);
> - each PRD AC to at least one positive and one negative or edge test (§B);
> - every story AC (S-180…S-198, GitHub #362–#380) to its tests (§C).
>
> Sources: PRD v1.3, spec v1.3, stories v1.3, task list v1.3, decisions D-01…D-78.
>
> The `AC-ID → Test-Case-ID → Observed → Pass/Fail/Drift` columns are filled in Audit Mode.
> Every **Observed** and **Result** cell is `PENDING` until the work is implemented and audited.
>
> Path prefixes: `A/` = `agents/bug-fix/app/bugFix/`, `P/` = `panel/`. Layers: L1 unit, L2
> component, L2.5 integration (local Supabase), E2E (Playwright), IC (in-container, deployed
> runtime), Live (fixture repo or real AWS), MR (manual or review evidence). Test IDs are defined
> in the test plan: TC §4, SC §5, CT §6, RT §9. Rows changed in v1.1 are marked **(v1.1)**.

## E. Audit-Mode fill-in protocol

When `verifier` runs Audit Mode after implementation, each row's **Observed** cell gets its evidence: test file and case, run result, and for IC, Live and MR rows the evidence document or link. **Result** becomes `Pass`, `Fail` or `Drift`. A drift result carries an impact class (Critical, Major or Minor) and an intent class (Intended, Unintended or Undetermined), and routes to `product-engineer`'s `activity-drift-reconciliation`. A row whose `(new)` test was not written is reported as `Fail` with "test not implemented", not as `Pass`. Rows pinned by a DF item are re-checked against the decision recorded for that DF. A known-red row (§D.3) that still fails because its finding hasn't been reconciled is reported as `Drift` with that DF's classification, not as `Fail`.
