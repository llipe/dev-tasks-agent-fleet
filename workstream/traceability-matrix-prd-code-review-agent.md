> Companion to [`test-plan-prd-code-review-agent.md`](test-plan-prd-code-review-agent.md) v1.0. It maps:
>
> - **PRD FR → PRD AC → story AC → test case IDs → layers** (§A);
> - each PRD AC to at least one positive and one negative or edge test (§B);
> - every story AC (S-204…S-215, GitHub #406–#417) to its tests (§C);
> - gaps, story ACs that rely only on live or manual evidence, and rows pinned by design findings (§D).
>
> The `AC-ID → Test-Case-ID → Observed → Pass/Fail/Drift` columns are filled in Audit Mode. Every **Observed** and
> **Result** cell is `PENDING` until the work is implemented and audited.
>
> Path prefixes: `A/` = `agents/code-review/app/codeReview/`, `C/` = `agents/code-review/agentcore/`, `P/` = `panel/`.
> Layers: L1 unit, L2 fixture pipeline (recorded GitHub + fake Bedrock), L2.5 panel integration (local Supabase), Live
> (deployed runtime and real webhook), MR (manual or review evidence). Test IDs are defined in the test plan: TC §4,
> SC-LIVE §5, CT §6, RT §9. DF findings are in test plan §10.

## E. Audit-Mode fill-in protocol

When `verifier` runs Audit Mode per story (S-204…S-215) and at the PRD rollup, it fills each §C row:

- **Observed** gets the evidence: the test file and case, and the run result. For Live and MR rows, it gets the verification-log row, the change record, or a link.
- **Result** becomes `Pass`, `Fail`, or `Drift`.

A `Drift` result carries an impact class (Critical, Major, or Minor) and an intent class (Intended, Unintended, or Undetermined), and routes to
`product-engineer`. A row whose **(new)** test was not written is reported as `Fail` with "test not implemented", not as `Pass`.
A known-red row (§D.3) that still fails because its finding was not reconciled is reported as `Drift` with that DF's classification,
not as `Fail`.
